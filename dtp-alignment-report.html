How to Read This Report

Be (Burma-Edition) words are the anchor. Each row is one Be word.

• Green (nw_match) = NW paired + words identical (case-insensitive)

• Yellow (nw_mismatch) = NW paired but words differ — genuine textual variant

• Orange (nw_sandhi) = iti-sandhi: DTP compound = Be base + Be particle (e.g. DTP gotamanti = Be gotama + nti)

• Purple (peyyala_range) = inside peyyāla expansion (one ...pa... covers many Be words)

• Gray (uncovered) = no DTP token maps to this Be word

• nw_delete = DTP has word but no matching Be word (DTP extra / Be abbreviated)

• both_skip = * in DTP, no Be consumed (both editions abbreviate)

• Green (ebt_match) / Yellow (ebt_mismatch) = EBT expanded word aligned via local NW

• ebt_delete = EBT expanded word with no Be match (most Be words consumed by main NW)

⚡ Iti-Sandhi Resolution

What is iti-sandhi?

In Pali, the quotation particle iti often merges with the preceding word through sandhi:

• gotamaṃ + iti → gotamanti (nasal ṃ → n before iti)

• sarīraṃ + iti → sarīranti

• sambodhiyaṃ + iti → sambodhiyanti

The problem: DTP keeps these as compound tokens (gotamanti), while Be splits them into base (gotama) + particle (nti). This is a 1-to-2 tokenization difference, not a genuine textual variant.

The fix: Post-NW sandhi resolution detects the pattern and tags these as nw_sandhi with links to both Be tokens (be_token_id → particle, be_sandhi_base_id → base word).

📝 Algorithm Notes

v4.2 Algorithm: Needleman-Wunsch + sandhi + local NW for EBT

Each sutta is split into sub-segments by peyyāla (...pa...) markers.

Peyyāla uses forward resync (window 10,000) to find next DTP word in Be — sets accurate boundaries.

Each sub-segment is then aligned using Needleman-Wunsch (MATCH=+2, MISMATCH=−1, GAP=−1). EBT words are excluded from main NW.

Post-NW sandhi resolution detects iti-sandhi patterns: DTP compound ending in nti/ti matched to Be standalone particle, with Be base word as orphan insert. Reclassifies from nw_mismatch → nw_sandhi and links both Be tokens.

Local NW for EBT: EBT expanded words are aligned against unmatched Be "insert" words (from main NW) in the same position range → ebt_match/ebt_mismatch/ebt_delete.

NW properly handles: reorderings (DTP lists sīla items differently), insertions/deletions (Be compound tokens like loko…pe…), genuine variants (DTP manussadhammā vs Be uttarimanussadhammā).

* rows always consume 0 Be words (both editions abbreviate).
